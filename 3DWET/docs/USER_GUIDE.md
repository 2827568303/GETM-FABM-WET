## 一、快速开始

### 1.1 启动桌面工作台

本仓库的常用入口是 3DWET Studio 桌面工作台。Windows 用户在仓库根目录执行：

1. 首次使用时双击 `setup_studio.cmd`。它会用 Python 3.10+ 创建 `.venv` 并安装 `requirements-dev.txt` 中列出的应用依赖。
2. 安装完成后双击 `launch_desktop.cmd`。工作台在本机启动服务并打开桌面窗口；要在默认浏览器运行，可使用 `launch_web.cmd`。
3. 从“案例管理”加载案例，或粘贴现有案例文件夹的绝对路径并点“打开”。GETM 案例须包含 `getm.inp` 或 `bathymetry.nc`；GOTM 原生单柱结果须包含可识别的 `gotm.yaml` 与 `output.nc`。

标准工作台运行不需要手动编译源码，也不需要从案例目录直接启动求解器。Windows 包使用 `3DWET/bin/getm_cartesian.exe` 及同目录 `runtime/` 下的运行库；请保留这两个位置及案例文件夹结构。

### 1.2 从案例到 2D/3D 播放

1. 在“案例管理”加载已有案例。修改已有配置前可用“另存为”复制案例，避免改动原始输入。若已有成功生成的结果，可直接进入查看步骤。
2. 新建案例时从“新建模型（前处理）”开始，导入湖岸边界与水深数据、生成网格，并按工作台步骤补齐初始条件、气象和河流等输入后保存案例。
3. 在“运行控制”检查所选案例和输出目录，点击“开始运行”；等待状态变为“完成”后再加载结果。若运行失败，先查看运行日志和诊断提示。已有输出时不必为了播放而重新运行。
4. 进入“2D 可视化”或“3D 可视化”，选择实际输出变量和显示方式，再使用时间滑块查看帧或点击播放。观察逐帧空间分布时用“自动”色标；跨帧比较同一颜色尺度时用“锁定”或“自定义”。速度菜单是目标上限；如果实际帧率明显较低，可降低目标帧率。按暂停后可拖动时间滑块；3D 实际垂向变量可在画布中拖动旋转、滚轮缩放，播放更新会保留镜头。具体帧范围、色标及计时器说明见[连续结果播放](#桌面工作台中的-2d3d-连续结果播放)。

**Erken 藻类 cohort UI 演练（工程流程示例）**：已有一份独立隔离副本的真实 UI 记录，可用于查看 2D/3D 逐帧播放和播放中旋转镜头：[GUI 操作与逐帧记录](../../build/real-use-validation-20261022/erken-external-data-real-grid/cohort-split-mechanism-20261022/GUI_REPORT.md)。该旧测次中，`cyanobacteria_sDW` 和 `cyanobacteria_lowlight_cohort_sDW` 是逐个选择的变量，不是并排比较；记录包含两变量各24帧、色标和缺测值。它只证明该副本和浏览器会话中的结果浏览流程。其模型输入含默认/代理营养生态初值、单站气象空间广播、固定云量、零蒸发和温度端点延伸；两 cohort 的短期轨迹差异不能证明竞争效果、Erken 生态合理性或现场验证。科学限制和运行配置见同目录 [实验报告](../../build/real-use-validation-20261022/erken-external-data-real-grid/cohort-split-mechanism-20261022/REPORT.md)。

应用重启后会恢复上次有效的用户案例；若保存的目录已不存在，应用不会自动改选案例列表中的其他案例，请在“案例管理”重新加载或打开案例。pytest 测试临时目录不会写入持久案例记录，也不会进入最近案例列表。

运行结束或失败后，“运行控制”面板可能显示 FABM 状态检查汇总。它统计日志中内部、表层和底层的检查事件，不是变量数、格点数或实际修改总量；非零表示求解器曾裁剪越界状态。出现非零时请结合完整运行日志和结果检查，不能只凭这个计数判定结果错误或物理无效。运行中不显示最终计数；本次日志缺少完整可识别统计时显示“未提供”，切换案例或开始新任务后不会沿用旧计数。

恢复案例后，仪表盘会自动重新读取层数、生态模块、水格数和已有输出摘要；有输出时还会加载迷你空间分布图。首次读取期间会显示加载状态，案例尚无结果时会明确提示运行模型后查看；输出不可读或暂时被运行进程占用时，卡片会显示接口返回的原因。仪表盘摘要只汇总输出文件中实际存在的关键变量，不代表所有生态变量都已输出。

新建湖泊时，在前处理页一并选择边界 shapefile 组件和真实 CRS；水深可使用点、面等深区或 PolyLine 等深线。边界会保留所有外环并排除洞；上传等深线时必须明确选择数值水深字段（例如 `CONTOUR`），不会从 `OBJECTID` 等字段猜测。上传预览会显示源/目标 CRS、字段、深度范围和采样点数；确认边界预览、落入边界比例、生成网格后的水域格点与插值范围后，再保存到新案例。详细 Erken 官方等深线导入记录见[前处理验收记录](../../docs/audit/user-journey-20261021/erken-contour-preprocess.md)。

### Lake Ravn：从只读 GOTM reference 运行工作副本

1. 在“案例管理”打开官方 Lake Ravn GOTM reference 结果目录。该来源保持只读；不要在源目录启动求解器或编辑文件。
2. 对该案例选择“另存为”。确认勾选“GOTM 单水柱：包含原始 output.nc、gotm_release.exe 与配置/输入”，并将副本保存到新的空目录。工作台会在副本中写入受应用校验的工作副本清单；运行时只使用副本里的 `gotm_release.exe`。
3. 加载新副本，在“运行控制”启动 GOTM；完成后从结果浏览、深度–时间图和时间序列查看副本中的新 `output.nc`。GOTM 是一维水柱模型：不要把它解释成 GETM 二维/三维空间格网，也不要据此声称水平空间验证。此流程只证明本机工作副本可运行和查看；训练/留出率定与科学验证仍需单独完成。



**Ravn 率定研究提示：** 本仓库有两个需要区分的离线结果。fresh-default 单参数试验以 ParSAC XML 中 `kNitrW` 范围最小化 DO 配对 RMSE；bounded optimizer 达到函数调用上限且结果贴近参数边界，未收敛，不能称为稳健最优、正式率定或完整 ParSAC。另一个实验按原样重放了 Aarhus 官方 `temp_do` YAML 配置；它在同一批 TEMP/DO 数据的 2001–2005 期间分数较好，但官方文件没有记载率定日期，因此该时期只能叫后期比较，不能称为 holdout validation。两者都不代表 GETM 三维率定或独立科学验证；普通桌面工作台不提供这些校准操作。报告分别见[单参数试验](../../build/real-use-validation-20261022/ravn-default-calibration/REPORT.md)与[官方 packaged TEMP/DO 重放](../../build/real-use-validation-20261022/ravn-temp-do-review/REPORT.md)。

Packaged `temp_do` 的 36.33 mg O₂/L 峰值经 USGS Benson–Krause 大气平衡筛查约为 374%，属于需进一步物理/数值审阅的红旗，不应仅凭表面平衡计算称为物理不可能；湖内过饱和可能发生，且气压 forcing 是否海平面订正尚无证据。该计算只使用 0–40 °C、0.5–1.1 atm 有效范围内的时间/层配对，假设为淡水（输出盐度为零）。静水压超出该溶解度公式的压力范围，未作外推。峰值 chlorophyll 与相邻日 DO 变化仅为背景线索；日数据不能分辨昼夜峰值，也没有完整生物氧收支或独立验证。默认和 packaged 的完整筛查指标、隔离脚本及限制见[筛查报告](../../build/real-use-validation-20261022/ravn-temp-do-review/REPORT.md)。

附近的 workshop `DO.obs` 在 1992-05-25 10:00 给出 −2/−3/−4 m 的 12.6/14.5/14.6；packaged 最近日输出是 10 小时前，按相邻原生模型层线性垂向插值后仍高约 8.17–9.83 mg/L。该时空差不是严格共址比较，且观测文件未自带单位，只使用报告中明确的 mg O₂/L 映射。`CHLA.obs` 虽映射到 Chl-a 模型变量，但源材料未提供观测单位，不能报告数值残差。详见报告中的事件对照及机器可读结果。

`Imported Random Lake` 是外部导入/验收中使用过的案例名，不保证存在于每份安装包或工作区。若你有该案例目录，可在“案例管理”中打开其绝对路径；没有该目录时选择当前安装提供的案例或自己的案例。案例名称、模型运行完成和动画能播放都不能单独证明科学结果已验证。

### 1.3 迁移现有项目副本

1. 在工作台打开“项目导入与物理设置”，填写源项目目录或 `project.json` 路径，并为新副本指定名称，然后选择“复制到案例库”。导入保留源文件，不会改写源项目或副本中的科学配置。
2. 查看导入结果中的“路径预检”：当前会检查 Fortran/GOTM `.inp`、`.nml` 中带文件/路径名称的引号赋值，以及 JSON/YAML 中名称明确包含 file/path/dir/directory 的字符串字段。项目内相对路径若目标文件也被复制，会显示副本内的相对目标；源项目内的绝对路径仍指向原目录，项目外绝对路径、缺失引用和越出项目目录的相对路径会分别计数，并列出最多三个例子。
3. 对源项目绝对路径、缺失或项目外路径，打开副本后按该输入类型的要求手动复制相关文件或更新配置，再检查输入页面和运行日志。预检只报告可能的引用，不会自动重写或修复配置；导入后源配置保持不变。

预检是有限的迁移提示，不代表项目完整可移植。它不解析二进制文件、环境变量/模板表达式、通配符、数组或复杂 Fortran 表达式，也不能确认路径字段的运行时语义；未识别的路径仍可能依赖源目录、机器环境或未复制文件。运行前请逐项核对案例输入。

若要把单个案例移动到另一台电脑或普通用户目录，可先在“案例管理”选择“另存为”，指定一个新目录，并勾选“包含结果”以便离线查看已有帧；复制完成后再移动整个案例目录。在新位置用“打开”选择该目录，检查输入文件、结果帧数和变量列表。若路径预检报告源目录绝对路径或缺失附件，移动后需先修复这些引用；历史来源记录中的路径只作溯源信息，不能保证对应文件仍存在。首次移动后建议保留原目录，确认新位置可打开并读到预期结果后再自行归档原件。

## 二、系统要求

### 2.1 仓库内 Windows 工作台

- 推荐环境：Windows x64。桌面模式由 pywebview 使用 EdgeChromium/WebView2；浏览器模式打开本机回环地址，不要求公网连接。
- 从仓库运行需要 Python 3.10+。`setup_studio.cmd` 使用项目的 `requirements-dev.txt` 和 `requirements.txt` 安装 Flask、NumPy、SciPy、netCDF4、pywebview 等依赖；不要在全局 Python 中混装项目包。
- 默认求解器是仓库自带的 `3DWET/bin/getm_cartesian.exe`。其 DLL 必须与 `3DWET/bin/runtime/` 一并保留。工作台“环境与启动诊断”可检查依赖和求解器加载；加载检查不等于完成模型计算或科学验证。
- 常规启动与运行不要求 GCC、gfortran、CMake 或 NetCDF-Fortran；这些工具只在开发者自行构建原生求解器时需要。当前仓库没有旧说明中提到的 `3DWET/scripts/build_model.sh` 一键构建脚本。

### 2.2 其他平台

本说明中的 `.cmd` 启动器和 `.exe` 求解器针对 Windows。Linux/macOS 的 Python/网页服务入口不代表当前随仓库提供的原生求解器包已在这些平台验证；需为相应平台配置可用的 `bin/getm_cartesian` 与运行库，并按“环境与启动诊断”检查。不要按旧版 WSL 步骤假定可直接使用 Windows 求解器。

## 三、目录结构

仓库内与日常使用有关的文件位置如下：

```text
仓库根目录/
├── setup_studio.cmd             # 首次创建本地 Python 环境并安装依赖
├── launch_desktop.cmd           # 启动 Windows 桌面工作台
├── launch_web.cmd               # 在默认浏览器启动工作台
├── requirements*.txt            # 工作台 Python 依赖
└── 3DWET/
    ├── app/                     # 服务端、桌面启动器、页面与静态资源
    ├── bin/                     # 随附原生求解器和 runtime DLL
    ├── case/                    # 随仓库提供的示例案例
    ├── model_builder/           # 案例与模型配置模板
    ├── src/                     # GETM、GOTM、FABM/WET 源码
    ├── scripts/                 # 数据辅助和离线绘图脚本
    ├── docs/                    # 用户指南与模块说明
    ├── build*/                  # 可选开发构建目录
    └── install*/                # 可选开发安装目录
```

桌面工作台由仓库根目录的启动器运行 `3DWET/app/launcher.py`；求解器从 `3DWET/bin/` 读取，Windows 运行库在 `3DWET/bin/runtime/`。活动案例路径由案例管理器选择，可以位于仓库外；运行日志与结果保存在该案例的输出目录。

## 四、求解器与开发构建

常规用户直接使用 `3DWET/bin/` 中随仓库提供的求解器，通过桌面工作台“运行控制”启动。手动从命令行运行二进制文件会绕过工作台对案例、运行目录、DLL 环境、日志和结果状态的管理，不作为推荐启动方法。

本仓库当前未提供旧版指南提到的 `scripts/build_model.sh`。从 GETM/FABM/WET 源码自行构建属于开发者工作，需要匹配平台的 Fortran/C 工具链、CMake 和 NetCDF-Fortran，并按源码项目各自的 CMake 配置构建；不要把旧版 `install/bin/getm_cartesian` 路径或未经当前构建验证的参数当作标准安装方式。工作台“环境与启动诊断”会报告实际解析到的求解器路径和加载检查结果。

## 五、运行模型

### 5.1 使用工作台运行

1. 在“案例管理”加载案例。运行已有案例前，先确认案例副本、输入文件和输出目录；修改配置前可用“另存为”复制案例。
2. 按需要检查“时间设置”、输出频率、模块和初始/边界输入。示例默认值不应直接视为目标湖泊的率定参数。
3. 打开“运行控制”，核对活动案例名称，点击“开始运行”。工作台按该案例的配置启动随附求解器并显示实时状态；运行期间不要用其他程序同时写入输出文件。
4. 状态变为“完成”后再打开结果页。若状态为“失败”或“停止”，先查看诊断与活动案例目录中的 `model_run.log`。旧输出文件可能仍在，但不代表最近一次运行成功。

### 5.2 运行时间与状态

运行时间取决于湖域网格、垂向层数、模拟长度、输出频率、启用的 FABM/WET 模块和机器性能。工作台的运行估算用于规划，不是性能承诺；模型成功运行或动画可播放也不等于科学验证已经通过。

## 六、配置模型

### 6.1 模拟时间设置

编辑 `case/getm.inp`:

```fortran
&time
    timestep = 30.0              ! 时间步长 (秒)
    start = '2020-01-01 00:00:00' ! 开始时间
    stop = '2020-01-31 00:00:00'  ! 结束时间 (30天)
/
```

### 6.2 垂直层数设置

编辑 `case/getm.inp`:

```fortran
&m3d
    M = 10    ! 垂直层数 (sigma层数)
/

&domain
    maxdepth = 25.0   ! 最大水深 (m)
    kdum = 5          ! 底部层数标记
/
```

> **重要说明**: 实际输出的 sigma 层数由 `kdum` 控制（层数 = kdum + 1），而不是由 `M` 控制。当前配置 `kdum=5` 会生成 6 层 sigma（-1.0, -0.8, -0.6, -0.4, -0.2, 0.0）。如需 10 层 sigma，需设置 `kdum=9`。

### 6.3 生态模块配置

编辑 `case/fabm.yaml` 启用或禁用模块。

**启用/禁用鱼类模块**:
```yaml
fabm:
  instances:
    PiscFish:
      model: wet/fish
      parameters:
        qStage: 0  # 0=禁用阶段结构, 1+=启用
```

**启用/禁用沉水植物**:
```yaml
fabm:
  instances:
    macrophytes:
      model: wet/macrophytes
      parameters:
        # 沉水植物参数
```

### 6.4 输出配置

编辑 `case/output.yaml` 设置输出变量和频率。

示例 - 输出水温、水位、叶绿素：
```yaml
netcdf:
  output:
    time_average:
      interval: P1D    # 日平均输出
      variables:
        - temp         # 水温
        - elev         # 水位
        - chlorophyll  # 叶绿素
```

### 7.1 输入文件列表

#### 从 shapefile 生成网格和水深

- 边界支持 Polygon/MultiPolygon；按 ESRI Shapefile 环方向识别外环和洞：顺时针外环形成湖岸片区，逆时针内环从水域掩膜中扣除。一个文件可包含多个外环，例如小岛和主湖岸。

### 7.3 气象数据 (meteo.nc)

在工作台“输入数据”页上传 CSV，通用列为 `date,u10,v10,slp,t2,rh,tcc,precip,evap`。也可直接导入 PROGNOS/SITES Malma 原始气象列：`TMSTAMP,SW_Rad_Avg,Air_Temp_AS_Avg,RelHumidity_Avg,MeanWS,WindDir,Rain_Total,AirPressure_hPa_Avg`。预览表可编辑数值；来源纬度/经度、URL/DOI、许可和时间标准字段可编辑。坐标以十进制度输入（纬度 −90–90，经度 −180–180）。

存在有效 `SW_Rad_Avg` 时，工作台保留实测入射短波（W/m²）到 `meteo.nc:swr`，并在生成的 GETM 配置启用 `use_measured_swr=.true.`；云量是独立的长波输入，可提供观测云量。若无云量列，工作台使用并在 provenance 中标注固定 `tcc=0.5` 代理。没有短波列时仍使用原有云量计算短波的路径。SITES Malma 窗口的压力字段原始元数据标注 Pa，但该段数字与 ERA5 对照吻合 hPa 量级，因此该输入工作流按 hPa→Pa 转换；这是窗口数值交叉核对，不代表修订了源数据元数据。direct measured SWR 的短波插值路径通过 10 秒隔离 smoke；当前 restart cache 未保存其两个短波插值端点，因此启用直接短波的 hotstart/restart 目前会明确停止。此输入模式仍需按具体站点审阅云量代理、空间广播和代表性，不构成现场或科学验证。

`date` 列可使用日尺度日期（如 `2020-01-01`），也可使用带时分秒的时间戳（如 `2020-01-01 01:00:00` 或 `2020-01-01T01:00:00`）。带时间的小时记录会保留时分秒写入 `meteo.nc`；日尺度输入仍使用原有日期格式。保存时会拒绝无法解析、重复或倒序的时刻；运行前体检还会检查 NetCDF 时间轴为有限且严格递增的一维序列，并核对对模拟时段的覆盖。逐小时数据请确保源 CSV 的小时记录完整连续；程序不推断或补造文件中缺失的中间小时，结束时段不足的延长规则仍按下方所述执行。

**启用与运行检查**：在工作台保存导入或编辑后的气象数据时，应用会同时将当前 `getm.inp` 的 `&meteo metforcing` 设为 `.true.`，只更改该项并保留其他配置。运行前体检和直接启动都会阻止两种配置不一致：存在 `meteo.nc` 但 `metforcing=.false.`，或 `metforcing=.true.` 但缺少 `meteo.nc`；提示会说明如何启用、补齐或关闭强迫。没有 `meteo.nc` 且 `metforcing=.false.` 是有效的无气象强迫配置。此配置检查只确保模型会按预期读取输入，不代表气象数据的空间代表性或科学有效性。回归验证：`.venv\Scripts\python.exe -m pytest tests/test_cfl.py tests/test_builder_native_namelist.py -q`，36 项通过；覆盖两类不一致、无强迫配置、直接启动拦截及保存时保留其他 namelist 设置。

**空间行为与确认**：当前气象输入是单站时间序列，保存时会将每个时刻的值**空间均匀广播到全格点**，不做空间插值，也不代表全湖观测场。系统以输入网格 `lonc/latc` 的经纬度包围框中心和来源坐标计算大圆距离。距离超过 25 km，或来源坐标不完整/未知时，会显示站点、网格中心及距离（未知时显示“位置未知，仍可广播”）并要求再次确认；取消确认不会生成 `meteo.nc`。这一距离提示是位置差异检查，不验证气象代表性或模型科学性。

上传接口即使返回 HTTP 200，也可能表示“需要确认”而不是保存成功。继续前应检查响应中的 `success`；当 `requires_confirmation=true` 时，核对显示的来源/网格位置并提交确认令牌后再保存。位置未知时，不能把 HTTP 状态码当作 `meteo.nc` 已生成的证据。

原始上传 CSV 会以安全化且不覆盖的文件名保存在案例 `Input/`。生成 `meteo.nc` 后，案例根目录的 `meteo_provenance.json` 记录原文件名和 SHA-256、上传 UTC 时间、来源 URL/许可/坐标、时间范围、列映射、转换/默认填充值、网格范围/中心、距离及确认状态；随案例目录移动。旧客户端仍可提交原有数据格式，但位置未知时也需要先取得并提交确认令牌。

工作台将单位归一化到模型输入：气压 hPa 转 Pa；湿度/云量百分比转 0–1；`MeanWS` 与来向角 `WindDir` 按气象 convention 转为东向/北向 `u10/v10`；`Rain_Total` 是上一小时累计 mm，按 3600 秒转为 m/s，通用降雨/蒸发列仍按 mm/day 转换，蒸发强制为负值。存在实测短波时，白天有效云量按本地 GETM `solar_zenith_angle` 和 `short_wave_radiation` 公式反算，以使 GETM 短波强迫对应实测辐射；夜间沿用明确提供的云量。若测量超出反算可行范围，界面会显示限幅行数，应先核对单位和时间标准。

**缺测策略**：整列缺失的旧式可选列仍沿用页面默认值，并在草稿和来源记录明确列出；任何已提供列的空单元都会拒绝导入。系统不再悄悄向前填充，也不推断逐时降雨。若需合并站点或 ERA5 缺口代理，应先在导入前生成完整 CSV，并加入 `source_<field>` 列（例如 `source_wind`、`source_cloud`），每个时刻写明 `Malma observation`、`Svanberga observation` 或 `ERA5 reanalysis fill` 等实际来源。`meteo_provenance.json` 保存逐时来源标记、来源切换计数、时间标准、有效云量来源、被限幅的短波行数和单位转换。ERA5 是约 25 km 网格的再分析代理，不等同湖面站点观测；来源标记不代表其通过代表性验证。

日期必须至少有两个有效时步。PROGNOS 与 SITES Erken Malma 源时间使用固定 UTC+1 的标准时标签；Open-Meteo/ERA5 回补时应显式请求固定 GMT+1，并保留原始 API UTC offset。不得将 Svanberga UTC 小时未经换算直接拼入 Malma 时间轴。

### 7.4 河流数据 (rivers.nc)

**必需变量**:
- `discharge`: 流量 (m³/s)
- `temp`: 水温 (°C)

#### Erken 外部数据的使用边界

SITES 的 Kristineholm inlet 水化学是 2014–2023 年不规则抓样，通常约两周一次，冰期约每月一次；最长相邻样本间隔为 84 天。它适合作为边界水质背景或稀疏验证观测，不能直接当作逐日实测浓度序列。当前 SITES Erken Malma 水位数据是湖面水位，不是河流流量。SITES 目录检索未找到对应的 Erken/Kristineholm discharge 数据。

HydroShare PROGNOS Erken 示例提供 Kristineholm 日流量和水温，但流量来自 SMHI S-HYPE 模型；它是模型派生输入，不是 SITES 实测流量。该示例是 GOTM/SELMA 配置，也不等于 GETM/WET 复现。其 chemistry 文件头的单位前缀存在矛盾，不能照文件标签直接换算。

GETM/WET 河流 NetCDF 浓度约定为 `nh4`/`no3` (`gN/m³`) 和 `po4` (`gP/m³`)。SITES 的元素质量浓度须按元素种类转换并保留原始低于检出限标记；不要把 `TOT-N` 与无机氮组分相加，也不要把 `TOT-P` 当作 `PO4-P`。当前 UI 前处理器只写固定水质浓度，且不能按外部经纬度定位入流网格；动态序列需要经过审查的自定义适配器及已确认的河口网格位置。示例与来源审计见 [`build/sites-erken-inlet-chemistry-audit-20261022`](../../build/sites-erken-inlet-chemistry-audit-20261022/README.md)。

## 九、可视化

### 9.1 在工作台查看结果

先按第 1 节加载、准备或运行目标案例，再从导航进入“2D 可视化”或“3D 可视化”。已有结果案例可直接查看，不必重新运行；新运行则需等待工作台状态变为“完成”。

选择与案例输出匹配的变量后，可拖动时间滑块或使用播放范围控件逐帧查看。2D 适合水平场；3D 立体水体、等值面和点云模式，以及指定点垂向剖面和垂向平均，只支持元数据标记为真实垂向结构的 4D 变量。有真实垂向层的变量在 3D 中按水柱/层结构呈现；没有垂向层的变量仍可在 2D 选择器和 3D 主视图中使用，主视图会自动切换为“变量高度表面”（variable-height surface），其 Z 高度由变量值决定，不表示真实水深、水面或垂向结构。阅读此类图时请同时查看图例/色标，结合颜色判断变量数值，不要把 Z 轴高度解读为物理水深。无垂向层变量会在指定点垂向剖面和垂向平均选择器中禁用并说明原因；要查看其数值或水平分布，请使用 2D 或 3D 变量高度表面。切换案例或恢复的选择不再适用于剖面/平均分析时，相关控件会回到默认有效的 4D 变量。画布内拖动可旋转 3D 镜头，滚轮可缩放；若拖动难以精确控制上下视角，可使用“镜头仰角”滑块直接设定角度：0°为水平视线，正值从水面上方向下看，负值从水面下方向上看湖底。滑块范围为−89°至89°以避开垂直相机奇异值；俯视/仰视快捷预设仍可到达垂直方向，并同步显示为最近滑块值。“模型上下位置”滑块直接平移画面中的整个模型：正值上移、负值下移，不改变结果值或模型几何；它与镜头仰角和“垂向放大”各自独立。位置范围采用受限相机平移，避免模型移出画面。播放、切帧和变量重绘会保留所选位置，“恢复视图”将位置回中。镜头仰角只改变相机方向；仰视会沿用现有湖底/岸陆遮挡处理。单层水体播放会逐帧读取当前变量场和该视图所需的动态水深/高程信息；逐帧值域、水域有效性和湿网格拓扑继续按实际结果更新。播放范围、色标、暂停/失败行为和已知渲染限制见本节后续“桌面工作台中的 2D/3D 连续结果播放”。

点击播放时，若当前游标处于所选范围的起始帧（含）至结束帧（含）之间，且尚未到结束帧，就从当前帧开始；若游标在范围外或已到结束帧，则从起始帧开始。完整播放结束后再次点击也会从起始帧重播。暂停后继续会从当前帧的下一帧接着播放，不重复绘制暂停帧。播放会在结束帧实际完成绘制后停止。速度菜单提供 0.5、1、2、4、8、12 帧/秒，表示目标上限，不保证实际帧率。渲染耗时计入目标帧间隔；每帧仍须完成绘制后才调度下一帧，超时后也只继续一帧，不积压追帧。页面绘制回调受后台标签或嵌入式浏览器限频时，播放会在短暂等待后通过计时器继续调度，避免按钮保持“暂停播放”而帧号不动。因此三维场景较复杂或设备绘图较慢时，实际速度会低于菜单值；可选择较低速度，或切换到二维结果查看更连贯的变化。播放显示的是模型输出的离散帧，不会生成插值帧。

二维播放会有界预取最多 4 个未来帧；单次批量读取会在一次 NetCDF 打开中读取最多 4 帧，并在所选结束帧处截断。首次选择结果时仍需发现并确认输出文件，因此这不表示首次结果请求总共只打开一次文件。这用于减少播放中的逐帧等待，不代表实际速度一定达到目标值。查看动态结果时先选择“自动”，再观察时间/帧号、变量当前值和色标上下限是否随模型输出帧更新。自动范围按当前帧的有效值逐帧缩放；若需要跨帧比较颜色，改用锁定或自定义范围，并同时核对当前数值和时间。

“自动”色标按当前显示帧的有效值缩放，播放时 2D 和 3D 都逐帧更新上下限；播放帧本身已提供范围，不另发整段范围扫描请求。自动范围适合观察每帧的空间分布，但不同帧的颜色不宜直接作定量比较。需要跨帧比较时，先选择“锁定”并应用，范围会沿用该变量当前显示范围；需要指定一致边界时选择“自定义”并输入上下限。锁定和自定义模式均在 2D/3D 共用该变量的设置，变量或案例不同则分别保存。3D 连续水体会复用静态地形与拓扑缓存以减少重复组装；但逐帧有效单元的位置及生成的水体网格坐标、三角连接可能变化。快速更新会同步提交 field/missing 网格的坐标和连接关系，使绘图组件按当前帧网格绘制；这不保证所有变量或场景的固定性能。每个成功显示的帧仍对应真实模型输出，不省略中间输出帧。

播放计时器显示目标与实际帧率、成功显示帧数，以及整帧耗时和 P50/P95；分阶段耗时可帮助区分结果请求、数据解码、网格组装和绘图时间。耗时统计保留最近最多 60 个成功显示帧。长会话超过 60 帧后，窗口随新帧持续滚动更新；实际帧率按窗口内当前连续播放段的成功帧间隔计算。暂停或更改速度后会开启新的计时段，恢复后的首帧不把暂停时间计入帧间隔。目标帧率是上限；网格较大或浏览器/显卡较慢时，实际值会降低。3D 播放期间辅助空间剖面会暂停逐帧刷新，状态行会显示剖面时间；暂停或播放结束后，剖面会更新到主图当前帧。

检查播放是否跟上目标时，以计时器中的“实际帧率”和成功帧数为准，目标帧率只是调度上限。整帧 P95 表示最近统计窗口中 95% 的成功帧绘制耗时不超过该值；“超预算”表示单帧绘制时间超过目标帧间隔，“慢间隔”表示相邻成功显示帧的间隔超过目标间隔的 110%。测试动态变化时，可先选“当前帧自动（逐帧缩放）”，播放一段并观察帧号、输出时刻、当前值和色标上下限；自动色标随当前帧有效值变化。需要跨帧按同一颜色尺度比较时，切换到锁定或自定义范围，并确认两帧仍显示各自的新数值。

### 9.3 自定义可视化

使用 Python + netCDF4 + matplotlib 自定义绘图：

```python
import netCDF4 as nc
import matplotlib.pyplot as plt

# 读取数据
ds = nc.Dataset('output.3d.nc')
temp = ds.variables['temp'][:]
time = ds.variables['time'][:]
ds.close()

# 绘图
plt.figure()
plt.plot(time, temp[:, 0, 0, 0])  # 表面水温时间序列
plt.xlabel('Time')
plt.ylabel('Temperature (°C)')
plt.savefig('temp_timeseries.png')
```

要重跑官方 Ravn 配置，请在只读 reference 案例上选择“另存为”，并明确选择“包含原始结果和 GOTM 可运行依赖”，保存到新的用户工作目录。应用会把副本登记为 `official_gotm_reference_working_copy`；运行只使用副本目录内经过校验的 `gotm_release.exe`，新 `output.nc` 也写回该副本，reference 源目录保持不变。完成后在结果页加载该工作副本查看新输出。此流程是 GOTM 一维单水柱运行；不要用 GETM 水平空间网格、地图或三维湖面范围解释结果。一次官方配置原生回放成功仅证明该工程运行链路可执行，不代表科学率定、独立留出验证或观测适配已通过。

Ravn 是 GOTM/FABM/WET 的单水柱案例（水平网格 1×1），不是 GETM 三维湖泊模拟。二维页面对单水柱禁用水平地图，并提示改用 3D 垂向水柱、深度-时间剖面或时间序列；3D 显示保留 GOTM 的原生 `h+z` 深度层，水平坐标固定在单列，不表示湖面范围，因而没有可解释的水平镜头旋转。只有确有水平网格的 GETM 结果才适合旋转查看平面空间结构。

Ravn 官方 `.obs` 文件为时间、深度、数值等列，`wet_obs.xml` 规定模型变量对应关系，但这些文件/XML没有提供观测单位或质量元素 basis。导入时必须明确提供单位、basis、点位与深度方向；这些是导入映射元数据，不应描述成原始观测文件自带的属性。模型端 `sO2W/sNH4W/sNO3W/sPO4W` 以及 `wet_totN/P` 的 O2/N/P basis 仅在当前产品可确认的原生 WET 生产者版本或输出哈希绑定的元数据声明时自动提供；无来源声明的外部 NetCDF 保持 basis 未知，配对会拒绝不明确或冲突的 basis。当前审阅的官方 Lake Ravn 包中，`wet_obs.xml` 包含 TEMP、DO、CHLA、NO23、NH4、PO4、TOTN、TOTP 映射；其 companion `parsac/wet_cal.xml` 将 CHLA/TOTN/TOTP 映射到 `wet_*_calculator_result` 输出。`NO23.obs` 到模型 `sNO3W` 是 NOx 观测到硝酸盐状态的官方代理映射，不能解释为完整 NOx 状态；NH4/PO4 也在该包的 XML 映射中，不应标为 supplemental-only。两份 XML 对 CHLA/TOTN/TOTP 的名称差异必须按具体配置版本核实，不能只按文件名自动改写。

导入多个官方 `.obs` 文件时，在“实测数据”页的“官方观测文件导入”卡片中逐文件填写“映射到模型变量”和“文件单位”；湖泊 ID 与站位 ID 可继续使用上方默认值。`.obs` 内容不包含这些映射元数据，系统不再根据文件名推断变量，也不猜单位；缺少任一项时预览会要求补齐。CSV/XLSX 可从文件列读取变量/单位，或使用上方默认值，逐文件输入可覆盖默认值。预览会在每个文件标题下显示所选映射和逐行诊断；修改任一映射会使旧预览失效，需重新预览后才能应用。应用请求只接受签名预览中的同一组映射。

Ravn GOTM 剖面对比可在同一导入卡片中使用“只读配对：1D GOTM 代表性水柱”。先从本机目录浏览并选择 `.obs` 文件，为每个文件明确填写变量和单位，例如 `TEMP.obs → temp / degC`、`DO.obs → abiotic_water_sO2W / mg/L`、`CHLA.obs → wet_chla_calculator_result / ug/L`；`NO23.obs → abiotic_water_sNO3W` 是官方 NOx 到硝酸盐状态的代理映射。若所选模型变量要求 O2/N/P 质量 basis，只有在观测来源证据支持时才在该文件的 basis 框填写 `O2`、`N` 或 `P`；留空或冲突时配对会被拒绝，不会按变量名推断。然后填写湖泊 ID、观测组 ID、最大时间差，并从已映射变量中选择一个，点击“只读配对并查看”。观测组 ID 仅用于把所选剖面记录归为同一比较目标，不代表官方测站编码或空间坐标。页面列出实际文件名、SHA-256、变量/单位/basis 映射、可解析/排除行数及配对结果曲线；此操作直接读取所选文件和当前活动结果，不应用或写入当前案例的观测库。

配对数取决于实际选择的观测文件和审核映射。本次同一原生 Ravn `output.nc` 上，完整 workshop `TEMP.obs`（SHA-256 `059f102895e18a9770e14043d624bf4413b78ed7582edd548f9b552341f512e6`，11,904 个源行、11,832 条可用记录）在 12 小时最大最近样本距离下得到 5,813 对；预先筛选的 `selected_postspinup_obs/TEMP.obs`（SHA-256 `ec8286accde6fcc65f29bc46e58b380d90412bb970e341d2e7abaff0d78705c0`）仅含 3,540 条 1996–2005 记录，其中 73 条超出模型水层中心深度范围，得到 3,467 对。两者使用的输入行集合不同，配对数量不能直接互换；应核对页面列出的文件名、SHA-256 和排除诊断。配对成功仍只表示按已选映射和规则形成了数值对，不代表该单位映射、代表性或模型科学结论已通过独立验证。

只读代表性水柱目标只接受当前活动案例中带 GOTM 标识、单个水平列且提供一致原生 `h`/`z` 的输出；校验不通过会停止比较。该目标使用 GOTM 原生水层中心深度，不生成站点经纬度、CRS 或 GETM 网格单元。请先在工作台打开具有对应结果的 Ravn/GOTM 案例，再执行只读比较；不要把 Ravn 文件应用到其他活动案例。此路径仅支持一维柱模型比较；GETM 2D/3D 结果仍须通过已有点位流程提供经核实的湖泊、站位、坐标系和显式网格映射。配对成功只说明文件身份、单位、时间和深度插值规则可执行，不代表科学率定或独立验证通过。官方 workshop 观测页未说明再分发许可；使用已在本机获准访问的数据并保留来源记录。

观测导入中的“最大时间差（小时）”是观测时刻到最近一个夹住它的模型原生输出时刻的最大允许距离。两个输出时刻之间仍按时间线性插值；例如每日输出在正午有一个 12 小时最近距离，设为 12 小时即可配对。模型时间范围之外仍不外推。该设置不是相邻模型输出间隔的上限。

五轮外部工作流、随机湖泊及用于界面/求解器诊断的生成数据均是**合成数据**。随机种子让测试可复现，不会使其成为实测数据。模型图表也始终是模型结果；只有观测管理中明示来源、湖泊、测站、时间、深度、单位和文件记录的观测数据，才能作为观测曲线参与比较。不得只凭文件名或湖泊名称推断数据的实测来源。

藻类 cohort 的机制查看使用隔离实验 `build/real-use-validation-20261022/erken-external-data-real-grid/cohort-split-mechanism-20261022/`。操作入口为该目录中的 `run_experiment.py`、`experiment_manifest.json` 与 `case/`；它在同一真实 Erken 网格上将 cyanobacteria 的 12 个显式初始化状态按 50:50 等总量拆分，检查每个状态的拆分总量误差均为 0。随后只给克隆 cohort 改一个声明因子：`qLightMethod=2` 下 `cLOptRef` 从 23 改为 12 W/m²；consumer/foodweb 菜谱没有在此实验中作物种竞争对照。FABM 的 burial 与 inorganic-carbon 多实例端口已扩展至 `nPHYT=4`。该 24 小时 run exit 0，完成 17,280 个五秒步长，输出 24 个逐小时帧；逐帧 cohort 变量均有限且非负。

定量结果是两条 cohort 轨迹的差异：第一个输出帧均值为 0.149598818 与 0.149691777 gDW/m³，clone−source 为 +0.000092959；末帧分别为 0.141070353 与 0.143105303 gDW/m³，差为 +0.002034949（约为 source 末帧均值的 1.44%）。这只描述该配置中的模型响应。完整数值和运行配置见[机制实验报告](../../build/real-use-validation-20261022/erken-external-data-real-grid/cohort-split-mechanism-20261022/REPORT.md)与[逐帧审计](../../build/real-use-validation-20261022/erken-external-data-real-grid/cohort-split-mechanism-20261022/audit_results.json)；2D/3D 页面操作、帧率与色标记录见[UI 报告](../../build/real-use-validation-20261022/erken-external-data-real-grid/cohort-split-mechanism-20261022/GUI_REPORT.md)。UI 是逐个选 cohort 变量播放，不含并排比较；记录没有 zoom 测试。它不是学术竞争验证：没有 A（原单群）、B（等总量拆分但相同性状）、C（只改变声明机制）的完整三臂归因设计，也没有经验证的 Erken 营养/生态初值。正式的**科学竞争分析仍未完成**；不要把 cohort 差异称作现场竞争效应、率定或论文复现。

UI 报告记录的具体操作是：在隔离 UI 案例中，2D 依次选择原 cohort 和 lowlight cohort，各自播放完整24帧（目标12 fps，实测12.1与12.2 fps）；3D 选表层仰视，各自播放24帧（实测11.7与11.6 fps）。另在lowlight变量、目标2 fps播放时拖动3D画布旋转，帧继续前进并到达24/24，水体着色及色标仍在，水域376有效、缺测/几何缺失0。上述是本机当次实测值，不是帧率保证；它仅证明单变量连续播放及拖动旋转的该次操作，不证明并排比较、zoom 或物种竞争分析。
等总量克隆是明确选择的初始化分摊模式：在实例管理中选“藻类等总量分摊”，输入严格介于 0 和 1 之间、使来源与新实例都获得正份额的比例，确认预览列出的比例和全部被调整状态后再应用。服务只允许在该模型族的每个注册状态都于 fabm.yaml initialization 中显式声明、状态单位为已登记的 gDW/gN/gP/gC 每 m² 或 m³、且值有限可识别时启用；否则会拒绝该模式并保留默认完整复制。分摊会把来源实例的每个声明值乘以剩余比例，并把新实例值设为所选比例；不会缩放参数，也不会改写其他实例。此能力只按注册状态分摊初始 biomass share，不等于建立了不同物种/性状，也不构成竞争结论；不保证模型计算的总生物量、元素预算、C/N/P 储量或后续轨迹相同。不同模型族或参数配置的比较仍需基于科学设计审查初值、机制和单位。现有消费者/捕食者食谱不会自动接入克隆藻类，必须显式编辑并记录。

新增藻类成员后做机制比较时，可先建立三份独立案例副本：无新增成员、成员新增但目标机制关闭、相同成员且只打开目标机制。确保共享网格、强迫、时段、低营养盐初值、求解器和输出配置；输入若为低氮等人为机制设定，要在记录中明确写成代理值而不是湖泊观测。逐组检查模型注册、实例唯一名、消费者/碳/埋藏槽位和输出变量；运行后按同一湿格/时刻对比藻类 `sDW/sNW/sPW/sCW`、相关营养盐和机制通量。无成员→机制关闭的差异是“添加成员及其初值/接线”的综合效果；关闭→开启才是该机制开关的单因子敏感性。两者都不能单独证明真实物种竞争或科学有效性。Erken 44×18、24 h 的隔离操作记录见[三组敏感性报告](../../build/real-use-validation-20261022/erken-real-shape-nfix-paired-24h/REPORT.md)；该测次未在桌面界面导入验收，生态初值与低DIN设置为代理，结论不超过技术可运行和有限变量响应。

#### 选择指标并查看 2D/3D 结果

1. 先加载目标案例并运行模型。检查运行状态为完成后，再到结果页选择变量；变量列表只包含该案例实际可读的输出。缺少指标时，先检查 `output.yaml`、实例输出订阅和 NetCDF 文件，不要用空图或近似变量代替。
   当案例变量较多时，变量选择器上方会出现搜索框。可按中文/英文名称、变量代码或单位筛选；搜索只缩小原生下拉候选，不会自动切换当前变量。清空搜索恢复完整列表，若无匹配项会显示提示且保留当前选择。键盘用户可按 Tab 从搜索框进入下拉列表，再用上下键选择变量。
2. 2D 页适合比较水平分布、水位和表层/深度平均输出。垂向平均按各物理层实际厚度 `hn` 加权；缺失值、零/无效厚度、显式干格与 mask 格不参与计算，并对剩余有效层重新归一化。没有可用 `hn` 时使用 sigma 层界面或层中心推导权重；坐标也不可用时会报错，不会把第 0 层冒充水柱平均。二维变量和底面变量不做垂向聚合，保留原值。3D 页中“立体水体”要求真实垂向层数据；只有二维定义的变量可使用“变量高度表面”进行数值展示，但它不是物理水面或真实垂向结构。湖底地形是静态背景，也不是该变量的输出帧。
3. 选择实际变量后，时间滑块和播放范围对应此变量的真实输出帧及其 DOY 时刻。起止帧包含端点；首次点击播放时，游标在范围内则从当前帧开始，游标在范围外或已在终点则从范围起始帧开始。完整播放结束后重播会从起点开始；暂停后恢复从当前帧的下一帧继续，不重复绘制暂停帧。终帧绘制完成后停止。速度菜单为 0.5、1、2、4、8、12 帧/秒的目标上限。播放中拖动时间滑块会暂停播放，并刷新拖到的实际帧。渲染时间计入目标帧间隔；超时帧结束后至多调度一帧，不会积压追帧。复杂三维场景可能达不到菜单速度；降低速度有助于观看。
4. 在颜色与范围的“范围模式”中选择“当前帧自动（逐帧缩放）”，色标会按当前显示帧的有效值更新，播放时 2D/3D 每帧都会重新缩放。不同帧颜色不适合直接作定量比较；跨帧比较可选择“锁定范围”固定当前显示范围，或选择“自定义范围”输入一致上下限。自定义窄范围可能截色；已有锁定/自定义设置时仍按所选模式显示。
5. 三维画面可用“镜头”菜单切换斜视、俯视、仰视、正面、侧面或复位；点击“仰视”可直接从湖盆下方向上观察。在图内按住鼠标拖动可旋转镜头：向上拖动会降低视角，向下拖动会提高视角；越过水平面后可继续查看湖盆下方；滚轮可缩放。仰视到水面以下时，系统会自动隐藏遮挡视线的湖底、陆地示意面和陆地三角网格线，让当前变量水体保持可见；播放逐帧更新也会沿用该可见状态。回到水面上方后会自动恢复背景面和三角网格线。允许跨过上下极点翻转；接近正上方/正下方时旋转方向可能快速变化，若视角不便可用斜视/俯视/仰视预设恢复；菜单中的正面/侧面预设仍可精确对齐，俯视预设仍可从正上方观察。播放逐帧更新时会保留当前镜头。透明数据层适合看结构，不宜精确读色；定量查看请用不透明层，并参考色标、变量单位和当前层号。

   **播放中旋转复核范围**：在 Erken baseline 的 `cyanobacteria_sDW` 指标、frame 0–23、目标 1 fps 下，播放期间可在 Plotly 主图拖动旋转，水体与自动色标继续随帧更新，播放结束后镜头保持转向。此项实测只覆盖上述案例、指标和速度；缩放、平移、暂停/续播及变量切换时保持镜头尚未据此验证。播放速度受网格、变量和设备影响，请以页面计时器为准。

选择指标时同时核对单位、垂向维度、时间频率和变量说明。例如鱼类/浮游动物常以体积浓度（gDW/m³）表示，底栖动物/水生植物可能按面积（gDW/m²）表示；单位不同的变量不能直接比较数值大小。显示名可帮助识别实例，但不能证明该实例已按某个真实物种率定。

#### 保存并核对藻类—鱼类竞争配置

建议先用 Theoretical lake 练习，再将研究配置放在独立案例副本中。每个情景使用单独案例目录，避免 A/B 情景共享或覆盖 `fabm.yaml`、初始条件和输出文件。

做藻类或其他功能群的竞争对照时，先让两组使用相同网格、外部驱动、模拟/输出时段和求解器；核对两组初始总生物量及其 C/N/P 储量相等，再只改变研究问题指定的物种组成或模型机制。比较时检查体积积分的生物量、营养盐和溶解氧，并在有匹配观测时核对相同时间/深度范围的观测支持。把季节与时段选到能回答目标生态问题；例如冬季短时段不能代表春季或夏季藻华。将一个种群拆成两个相同参数实例、保持初始总量不变，只能作为数值一致性检查，不能当作种间竞争证据。若模型界面或输出未提供这些初始状态、通量或所需变量，应记录为未验证，不要用未支持的指标代替。

机制开关仅表示配置状态，不保证通量会被激活。运行后应核对相应通量诊断（例如固氮 `wNFix`）和营养限制诊断；若开关为真但通量仍为零，应记录为“本条件下未触发”，不能写成机制阳性结果。隔离的 Theoretical Lake 合成低 DIN 一日压力正控中，水体 NH4/NO3 初值为 0.001/0.005 gN/m³、入流 DIN 设为零，但 `lNfix=true` 的克隆 `wNFix` 仍全为零，开/关两臂输出数值逐项相同。该短时、人工强迫案例只说明这一配方没有触发可测固氮，不代表实湖条件或其他案例；详见[隔离试跑报告](../../build/real-use-validation-20261022/theoretical-lake-seasonal-competition/pilot-results.md#synthetic-low-din-mechanism-stress-positive-control-2026-10-22)。

5. 核对运行日志、完成状态和输出文件：应有多个实际输出时刻、预期结束时刻以及有限的湿网格结果。结果页分别选择各藻类和鱼类实例的实际状态变量，确认每个实例都有独立输出；再查看该鱼类实例的摄食诊断量（若该模型版本和输出清单提供）。A 中对应摄食通量应为正，B 中应为零或数值容差范围内为零；随后比较被捕食藻类与消费者状态的时间序列，并按相同有效湿格核对。仅看到曲线不同或 YAML 中多了一条关系，不能证明模型中发生了预期竞争。
6. 若要确认响应跟随猎物关系，再复制 A 情景，仅把鱼类猎物从藻类实例 A 改为实例 B，重新保存、运行和核对。记录案例目录、配置/输入文件、变量名、单位、时间范围和输出文件；总量变量（例如总叶绿素或总鱼量）不能替代单个藻类/鱼类实例的状态和通量证据。

## 十、常见问题

### 10.1 模型崩溃/段错误

**可能原因 1**: 初始条件不合理
- 检查 `fabm.yaml` 中的初始值
- 尝试使用更小的初始值

**可能原因 2**: 时间步长太大
- 减小 `getm.inp` 中的 `timestep`

**可能原因 3**: 河流水量过大
- 检查 `rivers.nc` 中的流量数据

### 10.2 结果出现 NaN

**可能原因**: 数值不稳定
- 减小时间步长
- 检查初始条件
- 增加扩散系数

### 10.3 编译失败

**错误: `fatal error: netcdf.inc: No such file or directory`**
```bash
# 安装 netcdf-fortran
sudo apt-get install libnetcdff-dev
```

**错误: `undefined reference to nf90_*`**
```bash
# 确认 NetCDF Fortran 库已安装
nf-config --flibs
```

### 10.4 运行速度慢

先区分求解器计算慢与结果播放慢。求解器速度受网格、垂向层、模拟长度、输出频率、活动模块和机器影响；播放速度还受设备、网格大小、所选指标数据量、三维质量档和绘图模式影响。播放菜单的帧率是目标上限，不是保证帧率；请以页面计时器显示的实际帧率和长帧统计为准。降低目标帧率或切换到 2D 可减少绘图压力。不要为追求动画速度随意加大模型时间步长；时间步长需要满足数值稳定要求。

### 10.5 FABM 未运行（getm_fabm 调用次数为 0）

**症状**: 模型运行完成但 FABM 模块未激活，日志显示：
```
WARNING: gotm_fabm.yaml not found.
WARNING: will continue with fabm_calc=False.
```

**解决方案**: 确保 `case/` 目录中包含 `gotm_fabm.yaml` 文件。

`gotm_fabm.yaml` 内容示例：
```yaml
fabm:
  use: true
  freshwater_impact: true
  repair_state: true
  feedbacks:
    shade: false
    albedo: true
    surface_drag: true
  numerics:
    ode_method: 1
    split_factor: 1
    w_adv_discr: 6
    cnpar: 1.0
```

### 10.6 日志文件异常庞大

先在工作台确认当前案例和运行状态，再检查该案例目录的 `model_run.log`。不要运行旧版指南中提到的 `scripts/remove_debug.py` 或 `build_model.sh`：这些路径不属于当前工作台发行流程。若日志仍快速增长，保存文件路径和运行时间段，检查当前案例配置与求解器诊断。

### 10.7 可视化脚本找不到输出文件

交互结果查看请在工作台“案例管理”中加载实际案例，再进入 2D/3D 结果页；不需要从 `case/` 目录运行脚本。仓库中的 `3DWET/scripts/visualize.py` 是读取固定历史文件名的离线脚本，只有其源代码中列出的 NetCDF 文件都存在时才适用，不能自动发现工作台案例目录中的任意结果。

### 10.8 离线绘图出现 "Mean of empty slice" 警告

**症状**: 运行可视化脚本时出现多个 `RuntimeWarning: Mean of empty slice` 警告。

**原因**: 浅水区域（水深 < 0.5m）被 crit_depth 过滤为陆地，导致底层（sigma=-1）数据全为 NaN，计算平均值时出现空切片警告。

**影响**: 不影响可视化结果，图仍会正常生成，仅统计计算时忽略 NaN 值。

**解决方案**: 可忽略此警告。如需消除，可在 visualize.py 中添加 `import warnings; warnings.filterwarnings('ignore', category=RuntimeWarning)`。

### 10.9 垂直层数与配置不符

**症状**: `getm.inp` 中设置 `M=10`，但输出文件中 sigma 层数为 6。

**原因**: GETM 的 sigma 层数由 `kdum` 参数控制（层数 = kdum + 1），而不是由 `M` 控制。当前 `kdum=5` 生成 6 层 sigma。

**解决方案**: 如需 10 层 sigma，将 `kdum` 改为 9：
```fortran
&domain
    kdum = 9    ! 生成 10 层 sigma (-1.0 到 0.0，间隔 0.1)
/
```

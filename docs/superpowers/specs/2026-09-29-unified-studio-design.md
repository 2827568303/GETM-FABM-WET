# 3DWET Studio 双端整合设计

用户要求结合现有功能重新设计；此前已选择Windows桌面平台。本轮按此指令将旧版项目管理、当前完整Web建模流程与原生网格编辑功能共同纳入，输出浏览器网页版和Windows独立桌面程序。

## 产品结构

采用同一后端和同一工作台界面。浏览器通过本机服务打开；桌面程序在独立窗口打开该界面，管理服务生命周期。现有科学计算代码与模型参数格式保留，不能将界面整合表述为新物理模型。

工作台采用深蓝导航、浅色工作区、青色状态强调，增大文字和交互区域。导航按项目、数据与网格、模型配置、运行、结果与率定分组。顶栏始终显示活动案例及任务状态；无案例时显示明确的操作入口，无结果时不得呈现模拟数值。

## 功能整合

| 来源 | 保留和接入 |
|---|---|
| 旧版GETM-FABM-WET | 项目化入口、最近项目、简明的配置到运行流程；旧project.json可检查并导入为新案例，不能继续固定运行test_case |
| 当前3DWET Web | 案例、GIS前处理、河流和气象、生态/鱼类/温室气体配置、运行检查和日志、二维/三维/剖面/时间序列、观测与自动率定 |
| 网格编辑器 | 水深编辑、陆水切换、区域平滑、河流点、撤销重做；通过共享Web界面提供，保存前验证并备份，运行时禁止修改计算输入 |

## 启动与分发

项目使用独立Python环境和完整依赖清单。启动器定位项目路径，等待健康检查再开窗口；端口冲突、缺依赖和求解器库缺失给出诊断。以健康接口验证服务身份，不能接入占用相同端口的其他程序。服务仅监听127.0.0.1。

Windows发布目录应含启动程序及必要Python依赖，明确模型和案例的位置；必要模型DLL需验证来源及可分发性。Web和桌面均支持从含中文与空格的目录启动。

## 数据与安全边界

原案例和用户已修改的getm.inp不用于测试写入。验证使用临时案例副本。网格保存保留NetCDF变量、维度和属性。服务的NetCDF访问继续使用统一锁，禁止多个线程直接调用库。项目迁移不得静默指向其他同名目录；失效路径显示需要选择案例。

## 验收

1. 双击Web入口后首页及核心接口成功；浏览器无阻断错误。
2. 双击Windows入口出现独立应用窗口；关闭及重新打开正常。
3. 所有旧建模功能可从新导航进入；网格修改、撤销、重做、备份保存和河流点可在两端使用。
4. 案例选择、配置保存、运行和结果读取使用同一实际案例，旧项目导入给出明确转换结果。
5. 临时小案例真实求解成功并生成有效NetCDF；与“窗口能打开”的检查分开记录。
6. 提供功能对照、依赖/启动说明、测试结果及交付目录。不把未验证科学过程标注为已验证。

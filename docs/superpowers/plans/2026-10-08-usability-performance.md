# 运行控制与湖泊展示实施计划

> **For agentic workers:** Use subagent-driven-development for independent tasks and validate changes on copied cases.

**Goal:** 完成用户指定的诊断跳转及修复、运行性能排查、内嵌示例优化、湖点位快捷编辑、全局及图表缩放和湖泊形态展示。

**Architecture:** 复用已有 Flask / pywebview 后端和案例状态。新增诊断动作模块与可视化缩放模块，保存操作使用案例身份和修订校验，写入前备份；原用户输入不被示例构建覆盖。

**Tech Stack:** Python / Flask / NetCDF / NumPy / Chart.js / Plotly / Leaflet / Canvas。

- [ ] 诊断：明确问题编号、配置文件、导航页、控件；提供有限的可靠修复，拒绝运行中、过期案例和过期配置，备份并重新检查。检查接口不改写驱动数据。
- [ ] 运行：复现实例计时、求解器计时器；修复进度日志丢失和反复读取大网格；测量合理输出与时段的收益。保留生态耦合，不静默放宽时间步长。
- [ ] 点位：以交互网格为入口快捷管理河口/测站，显示水域有效性，拖动或点选修改；保存前备份并与运行互斥。保留撤销操作。
- [ ] 展示：沿实际陆水边界生成湖岸、水面与湖盆，正深度掩膜、正确坐标和垂向比例，支持无结果时预览地形。
- [ ] 缩放：Ctrl+滚轮改变界面比例，普通滚轮作用于图形；ResizeObserver 调整隐藏页恢复后的绘图尺寸，图表缩放、复位与全屏。
- [ ] 验证：后端回归测试、JavaScript 语法及真实 WebView DOM / 交互检查、案例副本性能和有限值验证。
- [ ] 交付：重新构建 EXE 和安装包；升级当前安装，验证快捷方式及用户案例保留，记录性能测量和边界。

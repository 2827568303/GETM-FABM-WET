# 用户完整建模流程与学术案例验收计划

> 本计划补充现有“整版诊断”“WET 多实例”“Ravn 观测率定”和“五轮完整验收”计划。它不替代这些计划，也不把局部 UI 检查或短时合成数据运行计为科学验证。按当前固定源码/求解器指纹收集证据；每次代码修改后立即同步桌面应用并确认实际服务版本。

## 用户需要完成的主流程

以新建案例副本为边界，复现一位用户从拿到外部数据到比较生态情景的整个工作：

1. **启动与迁移**：从任意普通用户目录启动网页/桌面工作台；移动整个案例目录到另一目录后重新打开；显示明确的缺失依赖、缺文件和路径修复提示。不得写入仓库原始案例或依赖开发环境中的隐式绝对路径。
2. **外部数据入模**：导入有来源与许可记录的气象、观测、地形/水深、河流或边界文件。预览文件识别结果、坐标/时区、单位、时间窗和缺列；未知字段不得自动猜成有效科学输入。输出导入清单、原始文件哈希和每项数据的真实/合成/代理来源标记。
3. **建立可运行案例**：引导用户从网格/水深、初始状态、强迫数据、生态模块、输出指标到预检。缺项在运行前指出；保留已填值；只在用户确认后构建和求解。记录预计与实际耗时、进度、日志及失败位置。
4. **观看动态结果**：在同一案例中逐一检查仪表盘、2D、3D、空间剖面、指定点位垂向剖面、垂向平均、时序和导出。2D/3D 连播必须逐帧更新值、色标和模型时间；用户可暂停、拖动、设范围及速度。3D 旋转/缩放/平移后继续播放，镜头与工具模式仍保持；慢帧不得追帧或卡死。逐指标标注缺数据、无效范围、单位和是否为真实求解器变量。
5. **生态对照情景**：将基准案例事务性复制为对照与干预两份；通过生态实例界面新增/克隆鱼类或藻类，确认唯一实例名、实际资源/捕食端口及初始化值；查看变更预览后保存并原生求解。并排比较同时间、同单位的生物量、营养盐、温度/氧、食物网通量和全域/点位时间序列。不得把单个输出数值称为“合理”；检查有限/非负状态、湿格覆盖、质量/元素收支可用性及预期机制，并将观测支持、机制一致性、尚待校准三类结论分开。
6. **交付与恢复**：导出含输入、来源/许可、配置、求解器/源码指纹、运行日志、结果、图和对照差异的可迁移案例包；移动后重新打开并复现相同输出哈希或记录允许的浮点差异。恢复原配置后逐字节核对原案例未改变。

## 三个国际学术工作流

学术案例必须先保留其原始模型维度/版本和论文假设；只有实际映射到本产品引擎、完成独立数据和数值核验后，才可声称本产品复现。1D 水柱案例不得伪装成 2D/3D 空间验证。

## 外部来源数据的 2D/3D 用户演练：Erken（瑞典）

- **来源**：SITES Erken 自动气象与水温剖面公开数据可作为真实外部输入；数据门户将相关产品标记为 SITES CCBY4 许可。其 Erken 背景信息 ZIP 说明内含官方 GIS 和湖泊水深/测深资料，可用来判断能否构造真实网格，而不是用合成圆湖顶替。检查实际文件元数据和许可文本后再导入。
- **步骤**：下载/选取同一时期的气象、温度剖面与湖泊背景图层；在导入预览核对测站与经纬度、坐标系、时区、时间覆盖、每个温度列对应的深度及单位；由背景GIS提取湖岸和水深，构造小尺寸 GETM 网格；逐项验证河流/边界、初值等必需项是否有真实来源，缺失项明确标成代理或不运行；若前置齐全，在隔离案例运行有限时段并查看真实2D/3D输出、时间滑块、色标和镜头旋转；在同一时刻把模型温度与对应测站/深度观测比较。
- **通过证据**：保存下载URL/引用/许可、源文件SHA、变量映射、CRS转换、测站和深度；网格湿格和湖岸与源GIS一致；求解器实际读入的气象/水深等与来源数据可追溯；模型2D/3D帧、温度剖面及观测比较可从UI重新打开；至少手工确认一组时刻/深度的NetCDF与页面值一致。
- **范围限制**：SITES 单一测站温度或水位数据不能单独补足全部三维边界和生态参数。若河流、初值、营养盐或测深数据不足，只能报告“真实外部资料导入 + 明确代理项的模型流程演示”，不能声称完整真实数据驱动或 Erken 科学验证。模型的空间变化是 GETM 计算结果；观测曲线仍是观测，不得互相覆盖。

### A. Lake Ravn（丹麦）：官方 WET 实测对比与率定

- **范围**：采用 Aarhus University 的官方 Lake Ravn GOTM-WET workshop 数据/默认配置与随附观测；这是原柱模型的观测流程，不是 GETM 三维湖泊网格。
- **用户动作**：从案例目录导入观测文件夹，预览每份 TEMP/DO/CHLA 等文件的列、单位、深度、时间和来源；选择已知身份的变量映射；显示可配对/被排除记录；运行基线比较；在明确声明的热身、训练和留出时段执行率定/留出评价；应用最优参数、重跑、恢复备份。
- **通过证据**：所有配对记录可追溯到文件/行号；时间/深度/单位配对的原始与转换值均可审计；错湖、未知站位、异物质基础和超深度记录被拒绝或隔离；优化每次运行与目标函数均有日志，留出集未参与优化；恢复前后源配置哈希相同。
- **不可声称**：工程划分不冒称官方原训练/验证划分；观测拟合改善不等于长期预测能力已证实；Ravn 不能自动匹配到其他湖或生成 GETM 的 `(i,j)` 位置。

### B. Lake Bryrup（丹麦）：2018 热浪对分层与藻类的影响

- **范围**：以 Chen et al. 2020 的暂时夏季分层湖热浪研究为复现目标；仅在取得论文匹配的一维 GOTM-FABM-PCLake 版本、完整校准配置/初始状态及真实气象/湖泊输入后，才运行基线与论文定义的增温/热浪情景。仓库现有 Bryrup WET 1.0 case 是独立模型版本/研究设计，不能视为 Chen 2020 的对应配置。不同 WET/GOTM/PCLake 版本不可混用；门槛和恢复步骤见 `build/academic-case-validation-20261021/bryrup/report.md`。
- **用户动作**：打开来源清单；核对气象、营养盐强迫和观察期；运行基线与干预副本；比较水温垂向结构/分层时长、溶解氧、营养盐、叶绿素 a、蓝藻峰值；查看逐时序与指标表。
- **通过证据**：两个情景除明确干预外输入和参数一致；温度强迫差异可追溯；输出覆盖同一时间窗；检查热浪场景下分层持续期及藻类峰值相对基线是否与论文所讨论的机制/方向一致，并记录本地差异及其原因。不得要求数值精确重合，除非复现了论文原配置、版本、参数和强迫。
- **不可声称**：该 1D 情景通过不能证明当前 3D GETM 网格/岸线/水平输运已验证；以合成地形扩展到 3D 时必须标为新情景，不是论文复现。

### C. Lake Arreskov（丹麦）：营养负荷/气候变化与生态状态

- **范围**：将两项独立研究分开：Nielsen et al. (2014) 是 Excel 接口的 0-D PCLake 参数 ensemble；Andersen et al. (2022) 是 1-D GOTM-WET 多策略校准 ensemble。仓库内 `lake_arreskov_denmark` 支持输入属于后者，不能代替 2014 PCLake；不得拼接两者的配置、solver、成员或 forcing。当前证据缺少 2014 论文匹配 Excel/PCLake build 与 900 成员、初态及气候/N/P情景数据，也缺少完整可执行的 2022 配置/参数集。两者均维持阻塞，分别按[Arreskov来源审计](../../build/academic-case-validation-20261022/arreskov-source-audit/AUDIT.md)中最小材料清单恢复后才运行。README 建议的 1990–2006 仅适用于本地后期 GOTM-WET 支持案例的监测不确定性说明。
- **用户动作**：检查气象、入流化学、出流、水位、管理操纵配置和时间窗；复制同一基线；独立更改营养负荷或气候强迫；查看营养盐、叶绿素/浮游植物、沉水植物及生态状态随情景的时间变化；输出情景差异和输入哈希。
- **通过证据**：成对情景只改变被标注的负荷/气候因素；重现原配置时输出和水文/生态时间窗完整；进行负荷/气候组合时有足够独立重复或参数集合且给出离散程度；检查清水/浑水转换是否由模型状态实际支持，标出临界阈值依赖、持续时间、参数不确定度。若本地输入或集合数不满足论文设计，仅报告可运行的敏感性示例，不称为论文复现。
- **不可声称**：单次短期运行、单一参数曲线或单次状态切换不能证明临界负荷、迟滞或管理效果；使用 2006 年后的数据需在结果中说明更高观测不确定性。

## 用户体验与性能验收记录

每条流程单独保存：固定源码/求解器/资源指纹、输入及配置 SHA-256、浏览器/桌面版本、操作时间线、运行时间、数据规模、输出帧数、动态观看的实际帧间隔与长帧情况、错误/警告、图像/导出、模型变量有限值和科学检查结论。只测试到功能入口不算流程通过；服务 200/进程退出 0/测试全绿均不能单独作为通过依据。

完整原生案例与学术案例、用户外部数据流程、合成 UI/求解器压力数据和正式五轮验收分开计数。修复后按对应范围复验；只有固定版本下的完整流程全部通过才算通过。证据目录建议为 `docs/audit/user-journey-20261021/`，保留失败报告，不回写原始输入。

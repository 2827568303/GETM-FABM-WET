# 3DWET 使用说明

Windows 用户：先运行 `setup_studio.cmd`，再双击 `launch_web.cmd`（浏览器）或 `launch_desktop.cmd`（桌面窗口）。求解器是 `3DWET/bin/getm_cartesian.exe`。Python 只负责界面和启动，计算在这个原生程序里。

## 跑滇池

案例在 `GETM-FABM-WET/3DWET/case/Lake Dianchi/`。网格是笛卡尔等距（`grid_type=1`，约 500 m，41×67，约 1150 个水格）。GETM 不能用三角网或非结构网求解，界面里也不再提供三角网格选项。

在「运行控制」里先做运行前体检，再开始。进度来自日志里的 `n=`。Patankar 的重复警告会被压掉，避免进度停在某个百分比、日志却被刷满。

## 运行监控

运行页上方的「运行监控」显示：

- MPI 进程数和 OpenMP 线程数
- 步进速度（步/秒，以及模拟天/墙钟小时）
- 预计剩余时间和 CPU 占用
- 每个进程最近的输出，可展开或收起

报错或长时间没有新步进时，这一栏会高亮。用来区分「还在算」和「卡死」。

## 看结果

水位、深度平均流速在二维结果里。水温、三维流速按层看：最底层附近是湖底，最后一层是水面。信息栏会给出表层均值、底层均值和两者之差。浅水混合充分时这个差可以很小。

关键量在 `output.nc`（每天）。其余水质在 `ext_wq.nc`（每周），点开变量才读取。

## 速度（本机短算，不是全年）

同一台 3 核 Linux 机器、滇池网格、步长 15 秒、模拟 1 天：

| 路径 | 墙钟 | 说明 |
| --- | --- | --- |
| 原生 `getm_cartesian`，关掉生态 | 4.4 秒 | 水动力+温度。1 线程和 3 线程差不多，网格小，OpenMP 帮助不大 |
| 原生程序，打开 WET | 323 秒 | 其中约 98% 在 FABM/WET。这一天能跑完 |

主路径用原生求解器。Python 不另跑一套水动力。

EFDC 滇池案例（约 515 个水格、步长 60 秒、只算温度、12 线程）在原电脑的 `TIME.LOG` 里 1 天约 3.5 秒。本机用 gfortran 编译开源 EFDC+ 没有链出可执行文件（源码按 Intel 语法写，整数当逻辑值用）。所以这次没有同机 EFDC 墙钟，不能宣称已经超过 EFDC。

Linux 上重编 GETM：`bash scripts/build_linux_solver.sh`。Windows 上现有的 exe 还没有本次 Patankar 限流，需要用仓库里的 MSYS2 脚本重编后，29% 刷屏才会在 Windows 上消失。

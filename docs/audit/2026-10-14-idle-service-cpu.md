# 本地 HTTP 服务空闲忙循环

检查隔离验收服务时发现，三个无模型进程、无浏览器活动的服务均在两秒墙钟内消耗约2秒CPU。独立最小Flask+实际LocalService的cProfile复现：2.007秒内6273635次函数调用，482597次select轮询，CPU1.96875秒。

原因：runtime.py传Waitress的asyncore_loop_timeout=.1，而实际安装版与随包Waitress的adjustments均将该设置转换为int，实际变成0。并非模型负载或求解器问题。

新增实际服务回归先失败：1秒空闲消耗1.015625秒CPU。改为有效整数1后，运行时25项测试通过，包含空闲CPU、后续health请求、保留HTTP连接关闭、服务终止及启动生命周期。

同一独立cProfile复验：2.001秒墙钟、CPU0.0秒（计时器分辨率内）、56次函数调用、4次select轮询。请求/trigger就绪会提前唤醒，未引入每次请求固定一秒等待。旧三个诊断服务已通过各自会话停止；它们使用旧代码，不能当作修复后证据。

该修复在第16次完整尝试之前完成；连续完整计数仍为0/5。

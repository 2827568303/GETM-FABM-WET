# 水体视图修复与视觉验收（2026-10-27）

## 本轮目标

修复 3D 水体在 Lake Dianchi 静态地形预览中看似平面的显示问题；让非矩形湿区轮廓和湖体厚度更容易理解，同时保持水深数据、湿网格拓扑和证据标签不变。

## 当前观察与根因判断

- **实测（应用显示，不是湖泊科学验证）**：桌面服务 `http://127.0.0.1:64257/` 加载 Lake Dianchi，网格 41×82、1,206 个湿格、10 个垂向层、20 个生态模块；该案例当前没有动态输出时步，显示的是静态地形预览。
- **实测（渲染诊断）**：水面网格存在，岸边侧壁 trace 存在 612 个三角形；湿区外形使用现有湿网格/边界代理，截图显示不规则轮廓。未提供可称为经验证真实岸线的地理数据。
- **确认的显示原因**：该案例水平网格跨度约 40.5 km，最大水深约 7.748 m。自动垂向倍率旧上限 300×使湖体显示高度约为主水平跨度的 5.7%，因此侧壁在默认视角下近乎不可辨。此次不是岸线数据变成正方形，也不是侧壁几何缺失。
- **已修正**：自动垂向显示目标调整为当前显示水平跨度的 12%，保留 2000×安全上限；留白范围扩展后 Lake Dianchi 自动采用 832×，场景纵横比约 12%。手动倍率仍按输入精确生效。垂向倍率是显示变换，未修改原始水深。
- **v162 边界留白修正**：之前视图范围被原始网格边界截断；Dianchi 湿区靠近西侧网格边界，预期约 3.4 km 的湿区留白被缩至约 0.5 km。现在绘图区允许坐标轴范围延伸到空白区域，实测 API 渲染回放的范围为 X −246.5 至 −220.6 km、Y 2573.4 至 2627.1 km，湿单元未裁切。
- **岸线平滑限制**：v162 将显示辅助 feather 的外缘与绘图区背景融合、向内渐隐；只在湿单元内作用，不改变湿网格边界、solver 拓扑或底深。岸线仍源自湿网格代理，不能据此称为自然/测绘岸线。
- **未确认项**：用户原先黑色床面片故障的唯一根因仍不确定；当前 Lake Dianchi 画面没有复现该黑片，不能据此宣称历史故障根因已修复。参考截图位置继续保留 `（待补充：参考图的具体路径或链接）`。

## 设计参考与采用理由

- [Nature Research Figure Guide — Preparing figures](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/)：明确轴标签和单位、使用可访问色带、减少背景网格与多余装饰。本视图据此保留单位/色标和数据层级，减少水体周围装饰线的竞争。
- [Nature Research Figure Guide — Building and exporting figure panels](https://research-figure-guide.nature.com/figures/building-and-exporting-figure-panels/)：强调有序布局和可读字号。本视图保持主画布为中心，并将数据图例和控制区分开。
- [3D-LAKES: a high-resolution 3D lake dataset, Scientific Data](https://www.nature.com/articles/s41597-025-05911-y)：作为三维湖泊空间/垂向结构与来源追溯的科学参考，不将该论文数据或其精度误称为本项目已拥有的数据。
- [COMSOL Graphics Window](https://www.comsol.com/support/learning-center/article/using-the-graphics-window-34211) 与 [QGIS GUI](https://docs.qgis.org/latest/en/docs/user_manual/introduction/qgis_gui.html)：采用其科学/地理软件“主画布突出、控制按任务组织、状态与显示分层”的交互先例，不复制具体品牌外观。

## 艺术指导取舍

使用浅色纸面与克制的蓝绿色水体表达；水深色面是唯一数值编码，湖体侧壁用低饱和蓝灰表达结构，不承载变量值。默认 relief 取 12% 的水平跨度，让水体可辨而不呈现 v160 截图中约 30% relief 的峡谷感。岸线遵循输入几何/湿格，不磨圆成理想椭圆、不补造地形；缺乏经验证岸界时始终标为“代理，未验证”。

## v163 静态水体层级修正（2026-10-27）

## v170 人视角默认取景与水体可见性复核

### Sol 高：现象判断与证据

- **实测（本地 UI）**：主服务 `http://127.0.0.1:64257/` 的 Lake Dianchi 3D 静态预览实际存在水面、等深线和边界来源说明；截图约 1093×919 px，绘图区估算约 798×609 px。v169 截图里的水体可见，约占画布宽度 70%、高度 45%，但观感较扁、略有漂浮感，浅蓝层级偏弱。因此当前截图不支持“这个页面完全没有水体”；用户报告的其它模型完全不显示尚未复现。
- **可确认的变量—现象关系**：本案例最大水深 7.748 m，默认自动垂向倍率 554.7×，自动 relief 仍限于水平跨度的 8%；静态侧壁统一限深到约 0.5 m 的显示裙边；v169 默认相机仰角约 25.7°，静态水面 opacity 为 0.48。水深/水平跨度比例、浅侧壁、偏俯相机及浅背景下的低对比共同符合“薄片/漂浮”现象，但不是“其它案例完全不可见”的已证实唯一根因。
- **候选原因与区分方法**：

  | 候选因素 | 可能的变量关系 | 区分验证 |
  |---|---|---|
  | 页面或图层状态 | 未进入 3D 主视图、surface trace 隐藏或渲染报错可能造成空画面 | 检查活动视图、`viz3d-status`、trace 名称与 `visible` 状态；切换 2D/3D 后复核 |
  | 水深/湿格输入 | 缺 `bottom`/`xc`/`yc`、没有正水深湿格或拓扑契约拒绝，会无法构造水体 | 查看 `/api/results/3d_surface`；核对湿格数、`display_topology` 状态和几何 trace 数 |
  | 相机/范围/缩放 | 镜头中心、方向、缩放或垂向位置异常时，数据仍存在但会移出可视区域 | 点“恢复完整图形范围”，记录 Plotly live camera 与 XYZ 范围，和新案例初始镜头对照 |
  | 边界裁切/坐标系 | 边界不相交或 CRS 不一致可能裁空水面；回退湿格会显栅格边 | 对比候选裁切状态及水面/墙/岸线几何，核对来源、坐标系和网格范围 |

- 上述是待区分的候选，不是单一根因结论。缺少用户报告的模型、变量/图层状态、相机状态及 API 响应时，“完全不可见”的具体触发因素仍为**不确定**。
- **岸线状态**：当前来源 `recovered-local-upload-cache` 明确为“边界代理裁剪（未验证）”。它可以使显示轮廓非矩形，但不证明轮廓等同真实地理岸线。需要边界数据来源、版本/日期、CRS 与许可后，才能验收自然地理形态；参考图路径仍为 `（待补充：参考图的具体路径或链接）`。

### Sol 高：Nature 视觉原则与取舍

- [Nature Research Figure Guide — Preparing figures](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/)：要求轴和单位可读、采用可访问色板、减少背景网格与多余装饰。用于保留真实水深单位、图例、清楚层级和来源标注。
- [3D-LAKES, Scientific Data](https://www.nature.com/articles/s41597-025-05911-y)：以可追溯三维测深数据和明确验证说明作为真实几何的参照。仅借鉴可追溯原则，不借用论文数据，也不声称本应用具备同等精度。
- 艺术取舍：蓝色水面作为第一视觉层，使用低斜角正交相机；保留米制水深与色标；床面保持隐藏；不添加未经数据支持的陆地高程、滩纹、水波或岸线细节；代理岸线明确标注未验证。

# 3DWET Studio scientific UI direction

Sol high-reasoning design memo, 2026-10-26. The user has approved the recommended restrained scientific direction and specified that the shell must not become monochrome, while model-data visualizations may retain variable-appropriate color.

## Product precedents

| Scientific application | Primary reference | Design lesson adopted |
|---|---|---|
| Nature portfolio figure standards | [Nature Research Figure Guide](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/) | Treat figures as precise scientific evidence: keep labels and units legible, preserve quantitative encodings, use clear panel hierarchy and avoid decorative effects that compete with the data. This informs exported result views, not the application shell layout. |
| Nature Scientific Data 3D lake dataset | [3D-LAKES: a high-resolution 3D lake dataset](https://www.nature.com/articles/s41597-025-05911-y) | Use real spatial/vertical structure and traceable data provenance as the standard for lake representation. It is a dataset reference, not a style license to invent terrain or claim that this application has equivalent bathymetric coverage. |
| ParaView | [ParaView User Guide: GUI and visualization workflow](https://docs.paraview.org/en/latest/UsersGuide/introduction.html) | Keep the render viewport dominant; separate pipeline/representation controls from the scientific image; make processing and inspection actions explicit. ParaView documents menus, dockable panels, toolbars and a central viewport, with panels for pipeline inspection and parameter changes. |
| QGIS | [QGIS User Guide: GUI, map views, panels and toolbars](https://docs.qgis.org/latest/en/docs/user_manual/introduction/qgis_gui.html) | Treat the map/model canvas as the primary work surface, with task panels that can be shown/hidden; distinguish navigation tools from editing and data panels. The main canvas should gain space when the user is inspecting a result. |
| COMSOL Multiphysics | [COMSOL 6.3 Desktop windows](https://doc.comsol.com/6.3/doc/com.comsol.help.comsol/comsol_ref_environment.18.02.html), [Graphics window](https://www.comsol.com/support/learning-center/article/using-the-graphics-window-34211) | Keep model structure, node-specific settings and graphics as distinct work areas. Expose camera, lighting and representation controls as technical tools tied to the current model context rather than decorative global chrome. |
| MATLAB | [MATLAB Desktop Basics](https://www.mathworks.com/help/matlab/learn_matlab/desktop_es.html) and [Desktop Layout](https://www.mathworks.com/help/matlab/matlab_env/overview-of-new-desktop-layout.html) | Use stable, named work areas for files/data, parameters and output; make side panels discoverable; preserve user orientation across workflow changes. |

These are established scientific tools, not a claim about a universal “best” design. The shared pattern is a neutral, low-distraction application shell around a high-information canvas, with task-specific controls and explicit state. This is a better reference for 3DWET than consumer dashboards or marketing sites.

The sources support a **layout and interaction** precedent, not a claim that any one product's exact colors or rating should be copied. 3DWET therefore uses warm paper, stone, pale sage and muted lake-slate surfaces with restrained ochre for provenance; color remains present in the application shell, while stronger chroma is reserved for quantitative model fields and explicit semantic states. In particular, “scientific” here does not mean black-and-white.

## Art direction

- **Character:** field-science workbench: calm, precise, material, and legible at long sessions. Avoid playful illustrations, pill-heavy cards, glossy shadows, saturated decorative accents, and monochrome black/white treatment.
- **Application-shell colors:** warm mineral paper and neutral stone for surfaces; pale sage for navigation/secondary panels; slate blue-green for selected/active controls; subdued ochre for provenance/pending states; muted red only for errors. Keep text charcoal-green rather than absolute black. Reserve high-chroma color for the model's quantitative data palette and selected model annotations.
- **Hierarchy:** one dominant model/data canvas; stable navigation grouped by workflow; a clear action strip; contextual parameters and metadata in a consistent inspector. Use hairline dividers, modest square corners, tight consistent spacing, and shallow surfaces. Remove decorative gradient stacks and unnecessary hero/card treatments.
- **Typography and density:** clear page titles, compact but readable control labels, tabular numerals for time/measurements, restrained capitalization, and consistent label/value alignment. Preserve current scientific labels, units, caveats, and provenance instead of replacing them with decorative copy.
- **Icons:** replace the whole 58-symbol set with one custom scientific glyph family: consistent 24-unit geometry, optical weight, square/precise terminals, simple silhouettes and clear domain semantics. Prefer grid, section, vector, layer, profile, and instrument motifs over emoji-like or toy-like objects. Icons stay monochrome in shell context; active state may use the slate accent. Keep symbol IDs and rendering API stable for all existing call sites.

## 3D expressivity

- In both dynamic and no-output static preview modes, keep the lake bed hidden by default, preserving the user's black-bed suppression request. A static preview uses a translucent blue cap at z=0 and restrained wet-grid boundary walls to show water volume. Never paint bathymetry as an opaque z=0 surface: it masks the water material and makes a volumetric lake read as a flat raster. Do not claim bed coloration unless a display-only bed is explicitly enabled. The shoreline remains a wet-grid proxy labeled unvalidated unless an authoritative boundary is supplied.
- If a candidate source-vector boundary passes the display-geometry checks, say that the source vector is used only for display clipping and remains an unvalidated proxy. If no candidate is present or it fails those checks, disclose the wet-grid shoreline proxy instead. The renderer's spatial alignment check is not scientific or geographic validation.
- Nature-figure direction: data use a single clear color encoding with a legible legend; structural water and walls use subdued non-quantitative materials; labels disclose proxy geometry and static status; avoid decorative geographic detail unsupported by source data. Preserve the distinction between measured/model output and schematic preview.
- Make dynamic 3D results read as a measured basin and layered numerical field through restrained layer separation and shoreline transition. Do not imply that a static bathymetry view contains temporal hydrodynamic fields.
- Shoreline geometry remains constrained by the supplied wet/dry mask. Display smoothing may improve legibility but must not be presented as a surveyed geographic coastline. A higher-resolution geographic outline requires an attributable source dataset; do not invent one.
- For Lake Dianchi, coastline geometry must be time-stamped as well as sourced: a recent century-scale study reconstructs boundary changes using historical maps, aerial imagery, and Landsat data through 2023, and reports substantial changes in perimeter and shoreline form. This supports requiring a date-compatible, attributable outline; it does not provide a ready-to-use vector file for the current case. See [Journal of Lake Sciences abstract](https://www.geores.com.cn/hpkx/CN/abstract/article/1003-5427/79674).
- When triangular display mode is selected, show a coherent triangular surface network and layer connections with enough contrast to read at normal viewport size. Use one subdued geometry tone (or small, systematic luminance steps by layer); geometry-line colors must never imply model variable values.
- Keep the chosen variable's color scale and colorbar as the sole quantitative hue channel. Geometry shading is explicitly presentational; preserve the current trace metadata and explanatory note that display triangulation is not solver topology or physical bed depth.
- Do not guess a black-bed root cause or change bed data/solver topology to obtain visual contrast. The black-bed root cause remains **uncertain** because the original artifact is not reproducible from the available scene evidence. The bed is hidden by default; any later reintroduction is a separate, explicit model-dependent choice.

## Scope and acceptance

Implement the shell system, complete icon catalog and triangular-display legibility as one coherent design pass. Preserve controls, navigation targets, data semantics and keyboard access. Accept only when existing UI tests and rendering regressions pass, the live source service reports updated asset references and bytes, and any native-window confirmation is stated separately.

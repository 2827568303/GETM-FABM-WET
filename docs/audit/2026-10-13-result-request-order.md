# 结果请求乱序与变量选择修复

日期：2026-10-13。独立功能验证，连续完整验收 **0/5**。

## 根因

前一轮实际语言检查发现：案例刚加载后选择水温，图形稍后可能又显示默认水深。源码中案例加载启动 `loadVariables()`，此时进入二维页可能再次调用它；每次返回都会清空重建变量列表，丢弃当前选择。此外 `updateViz2d()` 在每个异步请求返回后直接渲染，没有判断是否已有更新的变量/时步/层请求或案例切换。

## 修复及失败测试

新增 `test_result_request_order.js`，使用延迟兑现的实际 API 边界桩执行真实变量加载和绘图函数。在修改实现前稳定失败：refresh must preserve the current selection，实际 D，期望 temp。

- 重建变量列表时保留响应到达时仍有效的当前选择。
- 变量目录只应用最新请求；错误响应不清空现有目录。
- 案例加载增加修订号并清空旧变量缓存，防止旧目录继续被当作新案例元数据。
- 二维结果和无结果地形预览均仅应用当前请求、当前案例修订；过期错误也不再弹出误导提示。
- 主脚本缓存版本更新为 v31。

修复后测试验证：保留选择、旧目录晚于新目录返回、案例切换中目录返回、旧二维结果晚于新结果返回、过期错误及旧案例二维结果不渲染。

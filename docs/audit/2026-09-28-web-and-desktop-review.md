## 推荐方案

以当前3DWET服务为统一后端，复用现有建模界面，补齐经确认的另一版本独有功能；网页版使用本地HTTP服务，Windows桌面版使用独立窗口承载同一界面。共用案例和计算接口，避免两套参数保存逻辑产生差异。

先修复启动与环境诊断，再处理案例路径迁移和功能接入，最后构建Windows交付包。启动器先检查依赖、端口、模型和运行库，再等待健康检查成功后打开界面。失败必须显示实际原因和日志位置。

备选方案：保留两个独立程序并提供启动菜单，工作量小但配置重复；完全重写成原生桌面和新Web两套界面，维护与验证成本较高。

## Important source limitations

- Direct `model_service.py:16` selects a project-local case only for `luoma-existing-*`; other projects point at shared `Lake Luoma`. `runtime_config.py:92` rejects synchronization outside a project's own `case` directory. Generic create-to-run is therefore not a complete independent workflow.
- Direct `gui/package.json` packages `dist`, `dist-electron`, model and FABM resources, but not the Python backend/runtime used by `electron/python-runner.ts`. Backend lookup also uses paths relative to the app directory. Building an NSIS target does not demonstrate a clean-machine installation works.
- Direct DEM sampling assumes elevations relative to sea level (`grid_service.py:295`); current bathymetry paths and CRS behavior must remain the baseline for inland lakes.
- Existing-data import copies grid and boundary working files separately from `case`; its own manifest warns that grid/boundary edits require checking runtime inputs. Integration needs one authoritative case-input transaction.

## Core Fortran boundary

Read-only SHA256 comparison found 414 same-relative-path Fortran files: 405 byte-identical and 9 different. Differences: `getm/src/3d/getm_fabm.F90`; WET `abiotic_sediment`, `abiotic_water`, `fish`, `macrophytes`, `phytoplankton`, `sediment_exchange`, `wet_model_library`, `zooplankton`. Direct additionally has `getm/src/3d/getm_fabm_direct.F90`; current additionally has WET `inorganic_carbon.F90` and `methane.F90` (verified in directory diff).

The GETM coupling diff concretely changes `use gotm_fabm` in current to `use getm_fabm_direct` in Direct. These are different scientific engine variants, not just UI versions. Preserve current engine and GHG/fish behavior; expose an engine adapter only after separately validating compatible configuration, build and output contracts. Do not wholesale copy Direct `src` into current.

Recommended acceptance sequence: feature/API inventory and fixtures; authoritative project/case data contract; shared browser frontend and desktop shell; preserve current preprocessor/manual editor; validate run inputs and runtime ownership; preserve calibration/postprocessing; then clean-machine Windows packaging and bounded real-model smoke run. Source existence alone is not acceptance evidence.
